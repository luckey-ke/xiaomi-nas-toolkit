# 风险与边界

这份文档的用途是：**在动手之前就知道哪些事做不到**。所有"不能承诺"的地方都在这里，没有隐藏条款。

---

## 一、这是什么，不是什么

| 是 | 不是 |
|---|---|
| 一个针对特定固件的**研究性工具**，用于自有设备 | 一个稳定产品，无版本承诺 |
| 一套可复现、可验证、可回退的**操作流程** | 一个"点一下就好了"的黑盒 |
| 对**已实测固件**有效的方案 | 对任意固件都有效的通用方案 |

---

## 二、不可逆操作清单

以下事情做了就回不去，**执行前请确认你接受**：

1. **刷入任何非原厂配置后，无法通过官方渠道降级**。设备有 RPMB 门控的防降级机制，旧固件刷不回去。
2. **SSH 一旦开启，局域网内就是攻击面**。虽然默认仅密钥登录，但这是一条永远存在的入口。
3. **关闭原厂签名校验链路后，厂商 OTA 的行为不再有保证**。可能成功、可能失败、可能变砖。
4. **保修大概率失效**。厂商有权以"设备被非授权修改"拒绝服务。

可以回退的（见 [运维手册 · 卸载](04-运维手册.md)）：SSH 服务、目录守卫、自愈定时器、插件单元。卸载后设备能回到接近原厂的运行状态——但 root 能力本身仍在。

---

## 三、OTA 影响矩阵

固件自动更新默认是**关闭**的（`autoupgrade='0'`）。如果你手动升级，按情况分：

| OTA 类型 | 影响 | 恢复动作 |
|---|---|---|
| 只刷固件分区（常规） | 大概率无恙。root、SSH、守卫、插件都在 `/data` 与 overlay 层 | 重启后跑 `validate_v4.sh --reconcile`；异常则 `-Stage stack` |
| 清空 `/data` 数据区 | 自研插件与守卫配置全丢 | 重新部署（证书需有效） |
| 改动 `plugincenter` 协议或目录结构 | 目录守卫的合并逻辑失效 | 需要重新分析协议，**不保证能修** |
| 修补了 uci heredoc 注入点 | 无法再获取 root（已建立的 SSH 若未被清仍可用） | 无法重新部署；已有通道继续用到失效为止 |

**唯一诚实的说法：常规 OTA 大概率没事，大改就无法承诺。** 升级前跑一次 `-Stage check` 和 `-Stage probe`，能提前看出链路是否还成立。

## 四、能力边界

### 做不到的

- **不保证任意重启都无感**。已做多次受控重启演练（SSH 约 60 秒恢复、插件健康 200、状态保持），但极端情况（如 `/etc` 被整体重置）仍需重跑部署。
- **不保证插件永不被删**。守卫拦的是"对账删除"这一条路径。如果厂商改成"校验签名后才保留"，守卫拦不住。
- **不提供固件降级**。
- **不支持非 RP05 机型**。目录结构、组件协议都不同。
- **不做远程穿透**。所有访问都在局域网内。

### 已知的小毛病

| 现象 | 原因 | 处理 |
|---|---|---|
| 浏览器直开插件页 403 | 缺 App token，正常鉴权 | 用 App 打开 |
| `ssh host "keepctl ..."` 报 command not found | 非交互 shell 不加载 `/etc/profile` | 用全路径 `/data/minas-ssh/keep-plugins/keepctl.sh` |
| App 里状态偶尔慢一拍 | App 本地缓存 | 下拉刷新或重进 App |
| `scp` 报 SFTP 错误 | OpenSSH 版本太新 | 加 `-O` 走旧协议 |

## 五、安全检查清单

部署完成后，建议逐项确认：

```bash
# 1. 22 端口只对局域网开放（若你的路由做了端口转发，务必关掉）
ss -tln | grep ':22 '

# 2. 2323 root shell 有来源白名单
iptables -S INPUT | grep 2323
#   期望看到：若干 -s <你的网段> -j ACCEPT + 一条 -j DROP

# 3. 目录守卫只监听本地
ss -tln | grep 9310
#   期望：127.0.0.1:9310，不是 0.0.0.0

# 4. 磁盘休眠没被破坏
hdparm -C /dev/sda     # 空闲 30 分钟后应为 standby
```

另外两条运维纪律：

- **私钥备份到离线介质**（U 盘或密码管理器）。这是唯一能防"重装系统后进不去"的措施。
- **root 密码若设置过，不要和 SMB/米家账号同源**。部署日志里可能留下痕迹。

## 六、法律与伦理

- 本项目仅适用于**你本人拥有**的设备。
- 多数地区对自有设备做研究性修改是允许的，但**请自行确认当地法规**。
- 不要用它修改他人设备，不要用于任何形式的代部署服务。
- 漏洞细节来自公开研究（上游项目已公开），本项目不包含新的漏洞发现。

---

## 七、如果设备变砖

诚实地说：**没有软件层的解法**。

能做的准备：

1. 部署前确认设备里有重要数据的话已经备份到别处（root 操作本身不动用户数据，但 OTA 风险存在）。
2. 保留购买凭证——万一需要走售后。
3. 不要在没有把握的情况下刷非本机型的固件。

已经发生的案例里，本项目的操作顺序（先写副本、先预演、只改 `/data` 与 overlay）没有导致过变砖。但这不能作为保证。
