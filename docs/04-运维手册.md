# 运维手册

面向"部署完之后日常怎么用"。本文件同时部署到 NAS 的
`/data/minas-ssh/keep-plugins/使用说明.md`，设备上直接 `cat` 即可查看。

---

## 一、登录

### 密钥登录（日常用）

部署时会把别名写进 `~/.ssh/config`，所以只需要：

```powershell
ssh nas
```

`ssh minas` 等价。想用完整写法：

```powershell
ssh -i $env:USERPROFILE\.ssh\id_ed25519_minas root@<NAS_IP>
```

CMD 里路径写法不同：

```cmd
ssh -i %USERPROFILE%\.ssh\id_ed25519_minas root@<NAS_IP>
```

### 密码登录（密钥丢了时）

部署时如果设了 root 密码：

```powershell
ssh root@<NAS_IP>
```

输入密码时**屏幕上不显示任何字符**（连星号都没有），这是正常的。

### 图形化客户端

FinalShell / MobaXterm / Termius 都支持，认证选「公钥」，私钥选 `~/.ssh/id_ed25519_minas`，口令留空。若提示私钥格式不支持，是客户端太老（ed25519 需要较新版本）。

## 二、keepctl：调度管理

不用改 systemd 文件就能调整自愈策略。

```bash
keepctl status                 # 当前模式、间隔、启用状态、下次触发时间
keepctl set 5min               # 间隔模式（支持 30s / 5min / 1h）
keepctl at 08,12,15,18:00      # 日历模式：每天这 4 个整点
keepctl at "Mon..Fri 09:00"    # 日历模式：工作日 9 点
keepctl at 03:00               # 日历模式：每天凌晨 3 点
keepctl off                    # 停用（重启后保持停用）
keepctl on                     # 重新启用
keepctl apply                  # 手改了 keep.conf 之后让它生效
keepctl run                    # 立刻巡检一次（不改调度）
```

找不到 `keepctl` 时（比如系统升级重置了环境变量），用全路径：

```bash
/data/minas-ssh/keep-plugins/keepctl.sh status
```

### 两种模式怎么选

| 模式 | 适合 | 代价 |
|---|---|---|
| **间隔 2 分钟** | 想"被破坏后 2 分钟内自动恢复" | 每天跑 720 次（每次 0.3 秒、零网络） |
| **日历 4 次/天** | 不想看到频繁调度 | 18:00 之后被破坏，最长等 14 小时才自动修 |
| 停用 | 完全手动控制 | 失去自动修复；插件本身照常运行 |

**注意**：停用不影响插件运行，只影响"被破坏后能否自动恢复"。真出问题随时 `keepctl run` 立即修一次。

## 三、keep.conf：配置文件

路径 `/data/minas-ssh/keep-plugins/keep.conf`：

```ini
MODE=calendar                       # interval | calendar
INTERVAL=2min                       # 间隔模式的周期
CALENDAR=08,12,15,18:00             # 日历模式的时间点
ENABLED=yes                         # 是否启用
```

两种修改方式都有效：

```bash
# 方式一（推荐）：命令改，带格式校验
keepctl set 10min

# 方式二：改文本再生效
vi /data/minas-ssh/keep-plugins/keep.conf
keepctl apply
```

`keepctl` 的每条命令都会自动同步 `keep.conf`，所以它同时是"当前意图"的记录——备份、迁移时看这一个文件就够了。

## 四、status 输出怎么读

```
config    : /data/minas-ssh/keep-plugins/keep.conf
  MODE    = calendar                 ← 当前模式
  INTERVAL= 2min                     ← 间隔模式备用值
  CALENDAR= 08,12,15,18:00           ← 日历模式时间点
  ENABLED = yes
timer unit: /etc/systemd/system/keep-plugins.timer
  enabled = enabled                  ← 开机自启
  active  = active                   ← 进程活着
  rule    :
    OnCalendar=*-*-* 08,12,15,18:00:00
    Persistent=true
schedule  :
  NEXT                        LEFT     LAST                        PASSED
  Mon 2026-11-16 18:00:00 CST 6h       Mon 2026-11-16 12:00:03 CST 2h ago
```

**关键看 `NEXT`**。`active` 只说明 timer 进程在，`NEXT` 有值才说明它在调度。若 `NEXT` 显示 `n/a`，执行 `keepctl apply` 重建一次。

## 六、出问题的恢复阶梯

**按顺序试，别跳步。**

### 1. SSH 连不上

```powershell
# 先确认设备在线
ping <NAS_IP>
```

- `Connection timed out` → IP 变了或设备没开机。路由器后台查 IP。
- `Permission denied` → 私钥不对，或 root 密码改过。换密码登录试。
- `Host key verification failed` → 本机缓存了旧指纹：`ssh-keygen -R <NAS_IP>`

**重启 NAS** 能解决绝大部分情况（开机自启会重新拉起 SSH）。

### 2. 重启后仍连不上

钩子 + 自启双保险都失效了，说明 `/etc` 被大幅重置。重跑部署：

```powershell
powershell -ExecutionPolicy Bypass -File windows\deploy.ps1 -Stage check
powershell -ExecutionPolicy Bypass -File windows\deploy.ps1 -Stage root
```

⚠️ 这依赖客户端证书有效（约 1 年）。证书过期就在「小米智能存储」桌面端**重新登录一次**刷新。

### 3. 插件页面打不开

```bash
keepctl run                          # 先让自愈跑一次
systemctl status dockerctl           # 服务活着没
ss -tln | grep 9302                  # 端口在听没
curl -s localhost:9302/api/health    # 健康检查
journalctl -u dockerctl -n 30        # 看日志
```

自愈跑完后仍不行的，看 `/tmp/dockerctl/server.log`（服务日志，比 journalctl 详细）。

### 4. App 显示"需要下载"

```bash
keepctl run
# 然后看 install 字段是否为 True
```

仍为 `False` 的话，检查守卫是否活着：

```bash
systemctl is-active minas-catalog-guard
curl -s localhost:9310/api/health
cat /etc/config/plugin | python3 -c "import json,sys;print(json.load(sys.stdin)['settings']['server_list'])"
```

第三行应该输出 `http://127.0.0.1:9310/...`。若被改回云端地址，重跑 `-Stage stack`。

### 5. 一切正常但想从头核对

```bash
sh /data/minas/plugins/catalog/stage/validate_v4.sh --reconcile
```

逐项打印 SSH / 守卫 / 自愈 / 运行时独立性 / 健康 / 注册状态 / 钩子，最后输出 `VALIDATION OK`。

## 七、注意事项

1. **私钥就是钥匙本体**。`~/.ssh/id_ed25519_minas` 谁拿到谁就能 root 你的 NAS。别外传、别放网盘；换电脑拷过去就能用。
2. **浏览器直开插件页会 403**，这是缺 App token 的正常鉴权行为，不是故障。
3. **固件自动更新保持关闭**。升级前先问一句，或至少准备好重跑部署。
4. **别在没把握时卸载**。卸载会关闭 SSH，之后只能重跑部署或拆机。
5. **23:00 后改配置记得 `keepctl run`**。日历模式下夜间不会自动跑。
6. **备份在 `/data/minas-ssh/backup-v4-*/`**，每次部署前自动生成，包含所有被改过的原文件。
7. **Python 3.13 的证书坑**：见下节，本项目已内置兼容处理，但如果看到这条报错，说明你在用上游原始脚本。

### Python 3.13 / OpenSSL 3.5 的证书兼容问题

现象：

```
no working server CN (tried .0/.00/.1/.2/.20 suffixes)
或
SSLCertVerificationError: Basic Constraints of CA cert not marked critical
```

原因：Python 3.13 起的 OpenSSL 3.5 默认开启 `X509_STRICT`，而厂商 CA 证书的 `basicConstraints` 扩展没有标记 `critical`。**这不是中间人攻击信号**，只是厂商证书不合规。

本项目的 `core/nowsl_run.py` 已内置处理：启动时撤掉 `VERIFY_X509_STRICT` 这一位，**CA 链校验、有效期校验、主机名（SAN）校验全部保留**。所以正常不会遇到。

如果你绕过本项目直接跑上游 `xiaomi-nas-root.py`，就会撞上这个报错——此时用 Python 3.12 或更早版本即可。

另一个相关细节：服务端 SNI 只有 `nas.<uid>.<did>.0` 有效（`.1`/`.2`/`.00`/`.20` 都会主机名不匹配）。这是正常现象，工具的候选列表会自动找到 `.0`。
