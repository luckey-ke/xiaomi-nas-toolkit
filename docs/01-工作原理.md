# 工作原理

本文解释三件事：怎么拿到 root、怎么让 SSH 活下来、怎么让插件不被删。每一步都标注了"为什么这样做"，因为这台设备上的每一个设计都是被一次故障逼出来的。

---

## 一、root：七环链路

固件 1.0.9.462 起，早期工具依赖的 WebDAV 视频分段注入已被修补，本项目使用的是 462 之后的新链路（uci heredoc 注入）。七个环节环环相扣，缺一环就停在原地。

```
① mTLS 证书过 443 身份认证
   ↓
② get_pool_info 拿到 webDAV 账号与 UID
   ↓
③ WebDAV MKCOL 建"目录名含换行符"的目录
   ↓
④ 借 add_samba_account 的 uci heredoc 注入写入临时 SMB 共享（force user=root）
   ↓
⑤ 经该共享以 root 身份写 /etc/ld.so.preload 与 aarch64 触发库
   ↓
⑥ 任意进程加载 → payload 以 root 写 cron 任务
   ↓
⑦ cron 拉起 socat root shell(2323) + dropbear(22)，注入公钥
```

### 各环节要点

**① mTLS 认证**
设备用客户端证书做双向认证。证书由「小米智能存储」桌面端在登录时下发，落在 `%LOCALAPPDATA%\minasCert`。root 工具自动定位，不需要手工导入。

**② 凭据现场获取**
`get_pool_info` 返回 WebDAV 的用户名与密码。工具**不落盘**，只在内存里用来拼 Basic 认证头。这也是为什么每次部署都必须有有效证书。

**③ 控制字符目录名**
`MKCOL` 对目录名里的 `%0A`（换行）不做拒绝，而下游处理路径时按行切分——这一步是整个注入的入口。

**④ uci heredoc 注入**
`add_samba_account` 在写 uci 配置时，把用户可控字段拼进 heredoc。构造特定字段值就能在配置里"长出"一条额外的共享定义，且带 `force user=root`。

**⑤ preload 触发**
写入 `/etc/ld.so.preload` 后，**任意进程启动**都会加载指定 `.so`。触发库是现场用 keystone-engine 汇编生成的 aarch64 机器码，因此本机不需要交叉编译器——这是"免 WSL、免工具链"的关键。

覆盖 `/etc/ld.so.preload` 前，工具会先读回原内容，非空则备份；触发结束与清理阶段都会优先恢复原内容。

**⑥ cron 落地**
payload 以 root 身份写一个每分钟执行的 cron 任务。之所以用 cron 而不是直接执行，是因为 preload 触发时机不可控——等一分钟比猜时机可靠。

**⑦ 通道建立**
cron 拉起的任务做三件事：起 `socat` 的 2323 root shell、起原厂 `dropbear.socket` 的 22、把公钥写进 `/etc/dropbear/authorized_keys` 与 `/home/rootx/.ssh/authorized_keys`。

### 上游工具的边界

上游 root 工具**只获取本机会话，不做持久化**：重启后 socat 与 dropbear 服务都会消失（公钥有意保留）。持久化是本项目阶段 4 的职责。

同时它做了三件自保措施，值得知道：

- **账号槽位保护**：先查询现有 SMB 账号，只在空闲槽位新建；同名账号或槽位已满时**停止并保留原配置**。
- **preload 备份**：覆盖前读回原内容，非空则备份，清理时恢复。
- **失败路径也清理**：成功与失败都尝试撤销临时账号、共享与暂存目录。

> Windows 上没有 WSL 时，上游的清理通道（依赖 `nc`）不可用。`core/nowsl_run.py` 在运行时给它打了一个补丁，让清理走同一个 socket 通道——否则失败一次就会在设备上留下一个临时 SMB 账号。

## 二、SSH：为什么必须"修补"而不是"装一个"

原厂固件的 `dropbear` 不是标准的 dropbear：它把登录后的 shell 硬编码成 `/usr/sbin/mi-shell`——一个受限菜单，不是 `bash`。就算认证成功，你也进不到命令行。

所以做法是**就地替换那个字符串**：

```
原字节：/usr/sbin/mi-shell              18 字节
替换为：/bin/bash + 9 个 \x00           9 + 9 = 18 字节
```

实际替换必须**严格等长**，否则 ELF 内部偏移错位，二进制直接损坏。`/bin/bash` 是 9 字节，`/usr/sbin/mi-shell` 是 18 字节，差 9 字节，用 9 个 NUL 填充（C 字符串在第一个 NUL 结束，多余的 NUL 不参与解析）。

脚本里有一道硬检查：`mi-shell` 在文件里必须**恰好出现 1 次**，否则中止且不写补丁文件。这条检查救过一次——固件小版本更新后字符串位置会变。

为什么不用上游另一个方案（直接改 `/etc/passwd` 里 root 的 shell）？因为 dropbear 用的是**编译进二进制**的路径，不读 passwd。改 passwd 无效。

### 双保险

| 保险 | 机制 | 防的是什么 |
|---|---|---|
| 一 | `minas-sshd.service` 注册 `enabled` | 正常开机自启 |
| 二 | `/etc/syshotplug/pool/97.ssh-persistence` 钩子 | 厂商升级清掉 systemd 单元、或 `/etc` 被重置 |

钩子里有一条容易忽略的规则：**只 `start`，绝不 `restart`**。早期版本用 `restart`，结果存储池重挂载事件会把正在用的 SSH 会话踢掉——表现为"用着用着断了"。

还有一处 trick：`RequiresMountsFor=/data/minas-ssh/dropbear`，保证 `/data` 挂载完成后再启动（dropbear 副本放在 `/data` 上）。

## 三、插件：为什么会被删，怎么拦住

### 删除是怎么发生的

`plugincenter` 是原厂组件，负责应用市场的安装、升级、对账。它的逻辑是：

```
拉云端 server.list（全量插件目录）
  → 逐个比对本地已安装插件
    → 本地有、云端没有 = 已被厂商下架
      → 执行 preuninstall / uninstall / postuninstall
```

自研插件当然不在小米云端目录里。于是每次对账，它们都被判"已下架"然后删除——这就是日志里 `already taken down` 的来源。实测在两次对账中复现（22:59、23:13）。

**关键结论：事后修复没用。** 卸载动作发生在对账过程中，等自愈脚本发现时，服务单元、注册表、`/home` 目录已经被拆了。必须在**对账之前**干预。

### 目录守卫怎么拦

把 `plugincenter` 的目录源从云端 URL 改成 `http://127.0.0.1:9310/...`，中间插一个本地 HTTP 服务：

```
plugincenter → 守卫 → 云端
                ↓
         把 entries.json 里的自研插件
         合并进云端返回的目录
```

于是对账时"云端有它"，不会触发卸载。

三条设计约束：

1. **只监听 127.0.0.1**，不对外暴露。
2. **fail-closed**：云端不可达时返回 503，让 `plugincenter` **放弃本次更新**，而不是拿到空目录去对账。这是最关键的一条——宁可不同步，也不能删插件。
3. **响应形状校验**：云端返回结构变了就返回 502 并拒绝合并，不猜。

守卫本身无状态，只读 `entries.json`，改条目不需要重启它。

### 自愈补什么

守卫解决了"被删"，还有三个"状态不对"的问题：

| 问题 | 自愈的处理 |
|---|---|
| 重启后 `ports` 表里没登记 → 服务被厂商重建时清目录 | 按 `plugins.json` 重写 `ports` 表 |
| `plugincenter` 重建清单时把 `install` 置 `false` → App 显示"需要下载" | 用缓存的条目修正 10 个状态字段 |
| `/tmp` 是 tmpfs，重启丢日志目录 → 服务 5 秒崩溃循环 | 每轮 `mkdir -p /tmp/<plugin>` |

`install=false` 这一条值得单独说：**它不是显示问题，是功能问题**。点"下载"会去拉条目的 `mpk` 地址，而自研插件的 `mpk` 是本地路径不是 URL，所以必然"安装失败"。修好状态位，App 才会显示"打开"。

### 为什么运行时必须迁出 /home

`/home/<uid>/plugin/<id>` 是厂商**有权随时重建**的目录。插件跑在里面，等于把服务建在别人的地基上。所以：

- 服务单元指向 `/data/minas/plugins/<id>`（稳定）
- `/home/<uid>/plugin/<id>` 保留一份副本（兼容单文件部署工具）
- 网页目录是指向 `/data` 的软链

厂商清空 `/home` 时，服务不中断，自愈下一轮把兼容目录补回来。
